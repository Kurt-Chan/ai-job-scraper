## Fixed

- LinkedIn/Reddit postings only ever got a bare search-snippet fallback (title/description only, no company/location) because Firecrawl returns "Website Not Supported" for those domains → added an Exa fallback in `extract_postings()` that retries structured extraction on the same URL before giving up to the snippet. *(fixed: 2026-07-20)*
- `analyzeResume()` in the UI showed `"Unexpected token 'I', \"Internal S\"... is not valid JSON"` on failure instead of a readable error → root cause was `agent.run_claude()` not catching `OSError` from a broken/stub `claude` binary, so it propagated as an unhandled exception and `server.py` returned a plain-text 500 instead of the expected `{detail: ...}` JSON. Fixed by wrapping the `subprocess.run` call in `run_claude()` with `try/except OSError` → `RuntimeError` with an actionable message. *(fixed: 2026-07-21)*
- Dashboard defaulted to searching every resume-derived role with no location/pay/employment-type targeting, which combined with India-heavy indexing on Indeed/Glassdoor/JobStreet for the AI/n8n query terms used in testing → results skewed toward `.co.in`/`in.indeed.com` full-time listings. Fixed by adding role selection + a preferences string (chips: employment type, currency, location) folded into both `build_queries.md` and `analyze.md`. *(fixed: 2026-07-21)*
- Grid-view job cards had their action buttons at inconsistent heights across a row (extra stretched space appeared *below* the buttons instead of the buttons sitting at the card's bottom edge) → made each card a flex column with the button area `mt-auto`. The "Mark Status" button also floated alone on a wrapped line due to `flex-wrap` + `ml-auto` in narrow cards → made it a deliberate full-width row below Open Job/Cover Letter instead of relying on wrap behavior. *(fixed: 2026-07-21)*
- Even with the new location/employment-type preferences feature, a real run for an Egypt-based candidate still surfaced almost entirely India/Philippines results (`in.indeed.com`, `glassdoor.co.in`, `onlinejobs.ph`), including one job literally titled "...(India)" that still scored 75/"review" instead of being skipped. Root causes: (1) `DEFAULT_CONFIG.job_boards` in `agent.py`/`config.json` hardcoded `jobstreet.com` and `onlinejobs.ph` — both Southeast-Asia/Philippines-specific boards queried every run regardless of preferences, since `job_boards` is a fixed list unaffected by preference text; (2) `prompts/analyze.md`'s location rule ("score down or skip jobs that clearly conflict") was too soft to reliably force a skip. Fixed by swapping those two boards for globally remote-first ones (`remoteok.com`, `weworkremotely.com`), and rewriting the analyze.md location rule to be a hard cap (score ≤ 40, verdict "skip") when a posting's own content requires a different specific country than stated preferences — while explicitly telling it NOT to infer a mismatch from the URL/domain alone, since regional job-board mirrors often carry genuinely worldwide-remote listings. *(fixed: 2026-07-21)*

## Decisions

> Architectural and design decisions — the why behind the code.

- Claude is invoked via the `claude` CLI as a subprocess, not the Anthropic API/SDK directly — keeps the tool running on a Claude Code subscription instead of requiring a separate API key (per README "Support" section). *(observed 2026-07-20, predates this log)*
- Claude prompt calls only get `--allowedTools Read`, never `Write` — forces Claude to print results to stdout so Python remains the sole writer of `output/*.json`, keeping file-write behavior deterministic and testable. *(observed 2026-07-20, predates this log)*
- No database — all pipeline state is flat JSON in gitignored `output/`, since this is a single-user local tool with no need for concurrent multi-user storage. *(observed 2026-07-20, predates this log)*
- Exa is a fallback, not a Firecrawl replacement — scoped deliberately narrow (only retried when Firecrawl's scrape fails/returns nothing) rather than replacing Firecrawl's search or scrape wholesale, since Firecrawl already works for the majority of sites and Exa costs an extra API call. *(2026-07-20)*
- Resume analysis was split into two Claude calls (`analyze_resume()` → roles/skills only, then `build_search_config()` → queries) instead of one combined call, specifically so the UI can show roles for selection between the two steps. Costs one extra Claude subprocess call per run in exchange for that interactivity. *(2026-07-21)*
- Run preferences (location/pay/employment type) are a free-text string built from UI chip selections, not a rigid backend schema — chosen over fixed dropdowns (e.g. a hardcoded country list) because countries/pay rates are too open-ended to enumerate for a profession-agnostic tool; employment type *is* a small fixed set, so that one got dedicated chips (Full-time/Part-time/Contract/Freelance/Hourly). The string is passed as-is into `build_queries.md`/`analyze.md`, which already handle natural-language preferences. *(2026-07-21)*
- The waiting mini-game is pure front-end entertainment with no backend involvement — starts/stops tied directly to the progress-section visibility (`runAgent()`/`reset()`), so it never runs when not visible and never blocks or slows the actual pipeline. *(2026-07-21)*
- Adopt a per-job drafter-reviewer apply stage for high-scoring `apply`-verdict jobs, modeled on the *concepts* in MadsLorentzen/ai-job-search (MIT-licensed, 31.8k★) — but implemented from scratch for this project's architecture (Claude-CLI-as-subprocess, not a Claude Code slash-command framework). Draft with one `claude -p` call, critique with a second fresh-context call, revise with a third; drafts passed inline, never re-read. Borrowed ideas: two-agent separation, grounding audit, requirement coverage, structured reviewer edits. *(2026-08-16)*
- CV generation + PDF compile + ATS verification will be built as this project's own implementation — the *idea* of compile-and-inspect and `pdftotext` text-layer verification is worth adopting, but no code/templates are reused verbatim. *(2026-08-16)*
- **Typst is the CV toolchain — decided, not pending** (user approved the render on 2026-08-16; LaTeX is out). Typst = single ~50 MB binary, ~0.27 s compiles, deterministic output, clean ATS text layer; LaTeX = package-dependency friction (needed `fontawesome5` + `luatexbase` via `tlmgr`), verbose compiles (~0.8 s), and icon glyphs that extract as noise words (`Envelope`/`Github`/`LINKEDIN`) in the ATS text layer. Both installed locally this session without sudo: Typst binary → `~/.local/bin/typst` (v0.15.1), portable TinyTeX → `~/.TinyTeX`, Font Awesome 5 OTFs → `~/.local/share/fonts`, system `pdftotext` (poppler) for ATS checks. *(2026-08-16)*
- Typst gotchas discovered while styling the demo CV (each cost a compile error or phantom layout space): default `par.spacing` is 1.2em and silently inflates gaps between blocks (set `spacing: 0pt` and control spacing with explicit `v()`); `$` is math-mode (escape `\$`); `@` starts a label reference (escape `\@`); bare hyphenated identifiers are not interpolated in markup (need `#name`; but inside code context `#` is wrong); `leading` is a `par` setting not a `text` one; `grid`'s `gutter` was renamed `column-gutter`/`row-gutter`; `line`/`v`/`text`/`box` are not locatable via `query` (only headings etc. are); no built-in `icon()` in 0.15 and the `iconic` preview package doesn't resolve here — used Font Awesome fonts by codepoint via `str.from-unicode()`. *(2026-08-16)*
- Two more Typst spacing gotchas, found by rendering the demo CV and eyeballing it: (1) a bare `line()` is *inline* content, so a section rule becomes its own paragraph and picks up that paragraph's line-box height plus `par.leading` — the phantom band appears above and below the rule no matter what `v()` you set. Wrap it: `block(spacing: 0pt, line(length: 100%, stroke: ...))`. (2) `list.spacing` only applies to *loose* lists; a tight list (no blank lines between items) ignores it entirely and falls back to `par.leading`, so bullets render cramped. Set `#set list(tight: false, spacing: 0.35em)` to make the setting take effect. Both fixed in the demo at `/tmp/opencode/cv-demo/cv.typ`. *(2026-08-16)*
- Spacing verification method: since Typst's query API can't locate rules/text, gaps were measured by rendering PNGs and analyzing dark-pixel rows with Python (`numpy`/`PIL`) to find rule lines and text bands — that's what exposed the phantom `par.spacing` whitespace. Useful technique for any future layout iteration. *(2026-08-16)*
- Two Typst-to-ATS gotchas found by generating a real CV and reading its `pdftotext` output: a `grid` extracts **column-by-column**, so a two-column Skills grid gives an ATS every label first and then every value ("Tools: / Core: / Languages:" then three orphaned lists) — use one line per category instead; and a bare `~` is a non-breaking space that vanishes from the text layer, silently turning "~120 invoices/month" into " 120 invoices/month". Both now guarded in `prompts/cv.md`. *(2026-08-16)*
- CV generation is a whole-document generation, not template interpolation — Claude reads `resume.md` + `templates/cv.typ` and emits the complete Typst source, rather than Python filling slots in the template. Chosen because a profession-agnostic CV has no fixed section set (a VA's CV and a developer's CV differ in structure, not just content), and a slot-filling layer would have to enumerate them. Cost: the template is a style *reference* Claude may drift from, so the layout rules that matter are restated as prompt constraints. *(2026-08-16)*
- Step 5 failures are per-job and non-fatal — `generate_cvs()` catches everything per job and prints it, matching `generate_cover_letters()`. A missing `typst` binary or one uncompilable CV therefore can't take down a whole run that already spent Firecrawl credits. `pdftotext` is optional too: `_verify_cv()` returns no warnings when it isn't installed rather than failing. *(2026-08-16)*
